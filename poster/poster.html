Remember What Got Fixed

Emotion-Shift Memory saves only the past chats where a frustrated customer ended up satisfied. With that 400-token memory, an AI agent repeated 27% fewer mistakes on tasks it had never seen.

01 · The problem

Most AI mistakes make no noise

We studied 2,624 runs of AI agents helping simulated airline and store customers. When a run failed, the agent usually broke a store rule (refunding the wrong card, cancelling a ticket it should not) without any error message. A crash log cannot show what to learn.

02 · The idea

Let the customer's mood pick the lesson

Two yes/no questions sort every finished chat into one of four boxes. Only one box holds both a mistake and the fix that worked.

03 · How it works

Five steps, no vector database

  1. 1A chat with a customer ends.
  2. 2A mood detector puts the chat in one of the 4 boxes.
  3. 3For Frustrated → Satisfied chats, a rule writer (Gemini) writes one line: When … AVOID … INSTEAD …
  4. 4The line is added to MEMORY.md, a plain text file.
  5. 5In each new chat, keyword matching copies the 6 best-matching rules (at most 400 tokens) into the agent's instructions.

05 · Main experiment

Which past chats should go into MEMORY.md?

Kept the same: Agent: Gemini 3.8 Flash Mood detector: Gemini 3.5 Flash-Lite Same rule writer 400-token cap + keyword matching 59 test moments from unseen tasks Changed: which past chats are saved

Every condition picked from the same 100 past chats, then faced 59 exact moments where earlier AI agents went wrong, on tasks it had never seen. A repeat means the agent got that same moment wrong too. Lower is better.

How to read the p-values: compared case by case with no memory, our memory avoided 9 mistakes that the no-memory agent made, and made 2 that it avoided (exact McNemar test, p = 0.065). A p-value below 0.05 is the usual bar for “very unlikely to be luck.”

06 · Finding the mood shift

Which detector spots “frustrated → satisfied”?

600 real human chats labeled by people (150 per box, 2,709 replies). F1 for the “frustrated → satisfied” box, plus speed per reply.

Laya runs free on a laptop CPU. The agent test used Flash-Lite instead, because agent chats also contain tool errors and store rules that it can read.

07 · Learning over time

More past chats, fewer repeats?

Repeat rate after the agent has seen 0, 25, 50, or 100 past chats.

With only 59 tests, a swing of 2 to 3 cases moves a line by 3 to 5 points. Saving every chat reached 32% at 25 chats, then rose to 46% and 41% as more chats piled in. Fixed-only memory helped once it held about 18 rules (100 chats).

09 · Inside MEMORY.md (airline, first rules in each file)

Same rule writer, different lessons

Learned from unresolved chats36 rules saved
  • When a customer requests an escalation or transfer to a human agent: AVOID Ignoring or failing to immediately process the escalation request; INSTEAD Acknowledge the request promptly and initiate the transfer to a human representative.
  • When a customer complains about a flight delay in a recent reservation without providing flight details: AVOID Asking the customer to identify the specific reservation or flight before checking your system; INSTEAD Inspect their recent reservations and flight statuses directly to locate the delayed flight yourself.
  • When a customer requests compensation for a canceled flight that cannot be verified in system records: AVOID Repeatedly debating account records or refusing help without offering escalation; INSTEAD Clearly explain verification limits and offer escalation or transfer to human support promptly.
Learned from fixed chats (ours)13 rules saved
  • When A customer requests multiple changes including transferring a ticket or changing the passenger name to another person: AVOID Searching flights, seats, or bag fees before addressing whether ticket transfer is permitted; INSTEAD Immediately inform the customer that tickets cannot be transferred to another person before checking other changes.
  • When a customer requests to remove or change the number of passengers on an existing reservation: AVOID Attempting to modify passenger count directly or offering partial passenger cancellation; INSTEAD Inform the customer that passenger count cannot be changed and offer to cancel and rebook if permitted.
  • When Customer claims more passengers exist on a reservation than shown in records: AVOID Immediately issuing compensation for extra passengers or arguing without re-verifying; INSTEAD Re-check reservation details and politely clarify the exact passenger list documented in the system.

Rules that tell the agent to hand the customer to a human: 3 of the first 7 unresolved rules, 0 of the first 6 fixed rules. The store rules allow a hand-off only when the agent truly cannot help.

11 · Takeaways

What we learned

  1. Mood is a free teacher. When a frustrated customer ends up satisfied, the chat holds both the mistake and the fix, even when no error message was logged.
  2. Choose what to remember. Same rule writer, same 400 tokens: fixed chats only had the fewest repeats (19 of 59), versus 22 for unresolved chats, 24 for every chat, and 26 with no memory.
  3. Small and simple works. A plain text file, keyword matching, and a free CPU mood model: 1,218 lines of Python.
Limits. 59 test moments is a small sample: the gain over no memory is close to the usual bar (p = 0.065), and the gaps between memory types are not statistically significant yet. The customers in tau2-bench are simulated, and we tested one agent model. Next: more test tasks, real customers, and the free Laya detector inside the agent test.
